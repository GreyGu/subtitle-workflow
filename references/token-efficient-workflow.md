# 长任务的省 token 工作方式

适用于多集、多语字幕检索、审核和交付。目标是减少重复输入与长工具回传，同时保留可追溯证据。

## 开始前

每个大型独立任务使用新对话。只传技能版本、作品/季集、实际片源、目标语言、输入/输出路径、用户授权范围、当前进度文件路径和未完成事项。可复制 [task-brief-template.md](../assets/task-brief-template.md)。不要粘贴此前整段聊天记录。

## 执行顺序

1. 在任务目录创建 `originals/`、`working/`、`evidence/` 和 `final/`，只扫描用户指定目录。
2. 对候选文件运行 `subtitle_progress.py index`。先按 SHA-256 去重；同一指纹保留全部来源位置，原始内容只解析一次；与不同片源或音轨的适配仍分别核验。
3. 初始化 `progress.json`，按每集、每种语言记录阶段。完整候选索引、原始站点响应、检查报告留在 `evidence/`。
4. 搜索优先使用集数、语言、影片编号和发布版本。每个所需集/语言出现可核实的全文候选后，停止泛搜并开始核验。仅继续搜索缺项、局部字幕或片源不符的条目。
5. 每阶段执行前用 `check` 对照输入指纹和工具版本。用 `--config` 同时记录会影响结果的参数及所依赖的视频、音轨或共用参考的标识或指纹。结果可复用时跳过；目标稿变化只重跑该集、该语言受影响的阶段，共用参考变化时重跑所有依赖它的阶段。
6. 批处理复用通用脚本，不临时另写只运行一次的相同检查器。每轮只输出短 JSON 摘要：总数、通过/异常数、异常文件/集数、需人工决策项、完整报告路径。

## 给模型的工具结果

- 优先让命令写完整 JSON 到 `evidence/报告名.json`，终端只打印摘要。标准输出限制在约 1 KB；有异常时再读相关报告的摘要字段。
- 不回传字幕全文、完整 HTML/网页响应、每个成功候选的长元数据或已经读过的报告。
- 要判断译文时只提供有上下文的相关原文/译文片段、时间码和来源；一次聚焦少量相邻条目。语义判断所需上下文不可为了缩短而省掉。
- 进度变更立即写入本地 JSON。对话中仅保留当前结论、未解决问题和下一步，便于中断后从状态文件恢复。
- 完整报告可能含字幕正文和本地路径。分享前移除个人路径及无必要的受保护内容。

## 结束条件

停止搜索不代表字幕合格。只有用户要求的审核阶段完成、对应报告已写盘、异常已处理或明确列为未解决、最终文件经实际交付路径复读后，任务才算完成。摘要必须写清候选、结构、相对参考对时、逐句译文和音轨听校分别完成到哪一步。
