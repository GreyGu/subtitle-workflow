# 检索、文件路径和安全交付

## 版本确认与检索顺序

1. 保存用户给出的原始发布名，不因网站缺少压制组而换成另一部电影或剪辑版。系列编号、年份、国际发行名和影片编号需交叉确认；源语言依据实际音轨，而非国别/片名。
2. 在指定目录列出视频和字幕，读取视频元数据。可用 `ffprobe -v error -show_format -show_streams -of json VIDEO`；先发现实际可用工具，不假定工具装在历史机器路径。
3. 优先实际视频内嵌字幕、用户已有字幕及与发行版本明确匹配的候选；然后跨来源查找更好的译稿。内嵌不等于质量无误，仍须审核。
4. 检索可组合：完整发布名＋目标语言；原片名/国际发行名＋年份＋发行版本；IMDb 编号＋目标语言。中译英可用中文片名/国际片名＋年份＋English subtitles；俄文可用субтитры，中文可用简体/双语。先确认英语候选是全文翻译而非仅外语对白/标牌的局部字幕。
5. OpenSubtitles、SubDL、SubHD、射手/Assrt、字幕组发布页只是候选入口。实时确认它们是否可访问、当前获取方式、版本信息和授权要求，不把旧 API 或旧链接视为永久有效。

先阅读当前响应或服务文档；不要为绕过失效接口尝试不明来源的账号、密钥或下载器。若返回记录，沿记录中的下载链接获取，不猜文件编号。不同平台语言代码可能不同，不将 `en`、`eng` 或其他标签作为所有站点的固定参数。本技能不附失效即需绕过的下载接口，也不要求特定浏览器/账户。

遇到需要登录、动态页面或正常下载按钮才可获取的站点，使用可用的浏览器技能并遵循其说明及用户指定浏览器。公开 HTTP 下载不必打开浏览器。有限重试仍失败时保留错误和候选信息，转到其他正常来源；不宣称未取得的候选已被验证。

## 候选记录与选择

建议每个候选至少记录：页面 URL、字幕 ID、取得日期、影片/语言/发布名、作者或小组、原始文件名、编码、大小、文件指纹、全文/局部/听障类型、是否机器翻译/配音稿/转译稿及已验证差异。临时下载链接如含账户凭据或令牌，只保留不含秘密的来源记录，不进入分享包。

判断优先次序：

- 剪辑和叙事内容吻合，能与本地视频建立可靠对应。
- 正文完整，“信、达、雅”分别有依据，无系统性误译，人物语气和表达作用合适。
- 时间差可解释、可以安全校正。
- 播放器兼容性和阅读体验。

“发行名精确匹配”是强线索但不是验收结果；“高下载量/评分”也不是翻译准确的证明。两个网站可能分发完全相同的译稿，应比较标准化正文或原始指纹，避免将重复稿当成独立证据。

多集任务先按字幕文件 SHA-256 建立候选清单并去重，再逐集比较。每个所需集/语言至少有一个可验证的全文候选后，停止广泛搜索并进入文件与内容验证；继续检索只针对缺集、语言不符或版本不匹配项。把网页原始响应和完整候选报告保存到任务证据目录，对话中只返回命中数、缺失项、异常和证据文件路径。

## 工作目录与交付目录

新任务可使用下面的分层，不必强制创建无用途的空目录：

```text
任务工作目录/subtitle-work/<影片简名-日期>/
  originals/       原始压缩包和未修改字幕
  working/         解码、OCR、时间修正及补译副本
  evidence/        元数据、逐句对应、问题清单和抽查证据
  final/           已通过相应检查的待交付文件
用户指定目录/
  与视频相同主文件名.<目标语言标签>.srt（或保留 SUP/ASS）
  例如 movie.en.srt、movie.ru.srt、movie.zh-Hans.srt
  字幕备份与校验/<日期>/
```

Windows 的“下载”是显示名称，实际目录可能是 `C:\Users\用户名\Downloads`、重定向目录或用户自定义位置。优先用户明确给出的绝对路径；若只有“C盘下载”，解析当前 Downloads 位置或确认，不猜成 `C:\下载`。

其他系统也以用户指定目录为准。语言标签仅作一致命名约定；播放器可能使用 `zh-CN` 等不同命名，先确认兼容性，不为追求命名统一重命名用户未授权的现有字幕。通用技能、测试和分享包不得写死个人盘符、账户名、影片指纹或软件安装路径。

## 下载与编码

- 确认 HTTP 状态、实际文件头/内容、大小。扩展名为 SRT 的文件也可能是登录 HTML 或错误信息；`.gz` 应先验证压缩格式再解压。
- 解压前检查成员路径：禁止绝对路径、盘符、`..` 越界和指向外部的链接；解压结果应全部留在该任务新建目录中。字幕包中的可执行文件不需要运行。
- 保留原始字节再解码。常见俄语旧稿为 CP1251，中文旧稿可能为 GB18030；检测器只能给线索，需看人名和正常句子验证。不得忽略解码错误。
- 文字字幕通常另存为 UTF-8；是否带 BOM（编码签名）依据播放器兼容性。可使用 CRLF 换行兼容 Windows。输入输出的正文和时间必须可对账。
- 保留斜体、双人对白、位置等有意义标记。ASS/SSA 转 SRT 会失去排版，不能无声地换格式。不要将 SSA 内容仅改扩展名成 SRT。

## 图片字幕：SUP/PGS、IDX/SUB

这些格式保存的是字幕图片，不能像 SRT 一样直接检查文字。IDX/SUB 往往是一对文件，需一起保留。

- 先实际渲染，检查目标语言、简繁体、遮挡、色彩与显示起止。
- 全片统计有效显示事件，不能直接将容器“数据包数”当成句子数；有些包是清屏、更新或分段图片。
- 若需要补译或文字级完整度审核，先做 OCR（把图片识别成文字），对全部识别结果建立对应关系；重点查数字、姓名、标点、形近字和西里尔字母。
- OCR 没有逐条核对时，只能报告画面/时间和抽样文字验证。图像字幕保留原格式也可以是更稳妥的交付，不必为了得到 SRT 强行转换。

## 发布与失败处理

1. 验证最终候选的格式、正文、起止时间和未解决清单；不使用旧的“按空行分块”脚本。
2. 记录当前目标文件指纹，复制到带日期的备份目录并验证指纹相同。替换前发现目标已被用户改动则停止覆盖，保留两版。
3. 用临时目标文件完成复制和校验，再替换最终文件。不要修改视频，也不要重写未在请求范围内的其他语言字幕。
4. 从最终保存目录重新读取；核对文件名、大小、指纹、解析条数和关键首尾内容，必要时重新播放加载。工作目录输出成功不等于交付成功。
5. 用独立解析器复核，例如 `ffprobe -v error -count_packets -show_entries stream=codec_name,nb_read_packets -of json FINAL.srt`。其成功只证明可以解析，不证明译文无误。
6. 说明备份恢复方式、来源、补译身份、验证深度及剩余问题。保留校验所需小文件；临时大型模型或组件是否清理取决于当前权限，不绕过删除限制。
